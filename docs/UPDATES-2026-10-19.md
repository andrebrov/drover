# Tooling update — 2026-10-19

Portable mechanisms from the October 14–19 fleet revisions. Project policy and application drivers are excluded.

## Behavior

- Callsigns label workspaces; stable seat identifiers remain unchanged. `DROVER_SEAT_MODELS` applies both to initial spawn and resumed seats.
- `fleet-shared-nm` keys immutable dependencies by committed lockfiles and Node major. Opt-in preparation relinks persistent seats to their own key and archives real directories. `fleet-shared-nm check REPO HEAD` is the pre-build admission check a project hook can call.
- Migration reservations scan every numeric prefix width, including four-digit numbers, across main, fleet branches and existing reservations.
- One daemon classifier keeps language servers and MCP infrastructure out of build-process refusals. Stale base alerts judge only working/blocked seats; detached publication holds a seat even when native status says idle.
- Dispatch retains explicit current ownership, refuses unavailable live-work evidence, reports expired/unreasoned skips, understands final `WAITING-UNTIL` lines and revives stale in-progress work with prior evidence in the new scope. Pins remain until the bean completes on fetched main.
- Advisory file-claim admission is disabled; inspection remains. Ownership auditing reads native task snapshots and fetched main, never advisory claims or question TTL. Disagreement is UNKNOWN, not an inferred release.
- Briefs include canonical rulebook selection with a whole-file fallback. Historical precedents require landed ancestry, preserve revision/report provenance and redact excerpts. `FLEET_PRECEDENT=off` appends nothing. No private tuned policy or history corpus is shipped.
- Measurements publish a completion marker, writer hash, input fingerprint and computation time atomically. Old, incomplete or different-version observations are unavailable. The refill audit nudges owners; only the scoreboard publishes its counts. Standups consume stamped measurements and propagate ownership failures.
- The read-only observatory provides a compact kanban board, source/error notices and ancestry-based landing counts. Report prose cannot certify a landing. HTML escapes foreign content and cannot overwrite owner state.
- Finite routing remains opt-in through `state/safe-route/enabled`. Root grants bind all eleven job fields, brief bytes, source revision, prior task/report identity and expiry. The existing watcher owns the tick; legacy action lanes remain outside this boundary.
- Observer child timeouts reap the owned process group, unknown roster evidence preserves ownership, duplicate queue admission is refused and production checks require configured endpoints/commands. Status-only migration inventory is read-only, throttled, filename-exact and reports held/pending/destructive metadata.
- The portable main tripwire uses the project gate adapter (or the existing slot + clean verifier), confirms failures serially, checks the green base before attribution, names Jest/node:test files, excludes known bookkeeping from blame and publishes each completed evaluation before observing newer main. Missing fixtures are UNAVAILABLE. The project adapter must acquire the same DB grants as its push hook; no project SQL, fixture manifest or database driver is included.
- Installer preflight refuses unknown installed-only patches and uncommitted/untracked tool sources before any install. `--force` can replace a known historical version; it cannot waive drift. Uninstall removes only this checkout’s own links. Compatibility hooks live in canonical source, not a runtime patcher.
- Verifier single flight uses a kernel lease inherited by its worker; an unknown legacy lock owner is refused. BLOCKED final announcements also enforce publication, and a waiver cannot delegate publication to another person.
- Help and unknown-option refusal occur before shell/Python tools load project config or invoke services.

## Configuration and tests

See `examples/config` for optional settings. Shared npm preparation, migration/log checks, central graph linking and finite routing require explicit local configuration. No model, customer, cloud account, host, credential, private path or business integration is pinned here.

Run `bash tests/run-all.sh` (Python 3.12+, pytest, bash, Git, Node and the existing documented native tools). All external transports are fixtures. This does not install tools or restart launch agents.
